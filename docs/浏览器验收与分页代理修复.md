# 浏览器验收：修复仓库计数、新建入口和刷新返回JSON

## 一、结果速读

使用独立验证账号，在本机真实浏览器完成登录、仓库创建、普通/分片上传、文件搜索、代码查看、AI面板打开、退出、错误密码与直接访问/刷新检查。发现并修复3类功能问题，后端38项指定测试通过，前端生产构建通过（保留大chunk警告）。

4个通过浏览器上传的文件随后实际下载复核，大小与SHA-256全部一致。模型未启用，没有发送AI问题、付费调用、模型回答或语义质量结论；没有操作删除按钮或影响原用户仓库。

## 二、问题与修复依据

### 2.1 有仓库，却显示“我的仓库0、共0条”

**现象**：列表展示验证账号已有仓库，但首页和仓库列表计数都为0。前端读取的是API的total，不是前端本地数组计数出错。

**根因**：后端使用MyBatis-Plus的Page，却没有注册分页拦截器。查询返回数据，但没有正确执行COUNT与LIMIT。

**修改**：新增MybatisPlusConfig，配置MybatisPlusInterceptor与MySQL PaginationInnerInterceptor，单页最大100条。仓库查询在updatedAt后增加id排序，保证同一更新时间时分页顺序确定。

**验证**：新增2项真实MySQL回滚测试：5个同时间仓库按2/2/1分页、total=5/pages=3且无重复；公共仓库total只计PUBLIC，SQL限行生效。测试数据自动回滚。本机API实测total=2、请求size=1只返回1条，浏览器首页/列表显示实际数量。

### 2.2 首页“新建代码仓库”只跳到列表

**现象**：点击首页的新建按钮后没有创建窗口，需要再点一次列表新建。

**修改**：首页携带create=1查询参数；列表挂载后打开创建弹窗，再移除该参数，避免后续刷新反复弹窗。

**验证**：浏览器点击首页新建直接出现表单；空名称提交提示“请输入仓库名称”；填写名称与描述后创建成功并进入仓库详情。新建测试仓库ID23，未修改旧仓库。

### 2.3 直接打开/刷新仓库页面返回JSON

**现象**：退出后直接打开/repos/23，本应进入SPA并跳登录页，实际展示后端403 JSON。登录时刷新同路径也存在页面被当成API的风险。

**根因**：Vue页面路径/repos/:id与后端/repos/:id重名，Vite和Nginx把/repos/整体代理给后端。

**修改**：前端Axios统一使用/api，AI的流式fetch也改用/api/ai；Vite只代理/api并去掉前缀。两份Nginx配置同步/api/到后端，其余路径保留SPA fallback，并设置上传体积/代理等待参数。后端8080接口路径保持原样。

**验证**：未登录直接打开仓库地址后跳登录页；正常登录后直接打开和刷新恢复仓库文件界面；/api登录、分页、文件列表、普通上传和分片上传均经页面复测。额外HTTP检查确认/repos/23返回text/html，/api/repos/my返回分页JSON。

Nginx是配置同步，本轮没有构建或部署Nginx容器，不能据此声称生产代理验收通过。更换前端构建时应同时更新对应代理规则，避免混合新旧版本。
